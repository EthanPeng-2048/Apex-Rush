# Apex Rush Online 设计方案

## 1. 项目概述

本项目目标是在 Windows 上交付一款**纯本地、零外部运行时依赖、双击即玩**的多人 F1 竞速游戏。最终产物为单个 EXE（可附带同级配置文件），面向 ICT 课局域网环境，单局 4–8 人。联机完全在局域网内完成，不依赖公网服务器、云服务或信令通道；主机创建房间后自动广播，其他玩家自动发现并输入相同房间码加入。

**核心路线**：C++ + Raylib（渲染/输入/窗口）+ qu3e（轻量刚体碰撞，接触点映射部件损伤）+ 自写 4 轮射线悬挂 Simcade 车辆动力学（组合滑移轮胎、磨损/温度、部件损伤气动、DRS/活动翼/ERS）与辅助层 + ENet（主机权威网络）+ udp-discovery-cpp（局域网自动发现）。

**定位**：物理与规则系统深度对标 F1 25 级（轮胎磨损、部件损伤、DRS、2026 活动翼、Override 超车模式全量实现），画面走低模清爽风格化路线（手感对标 Real Racing 3 / Monoposto 一档拟真），守住 10 MB 体积与核显 60 FPS。

## 4. 技术选型

### 4.1 Raylib：渲染、输入、窗口

Raylib 是极简 C 游戏库，预编译静态库可直接下载，零外部依赖，核心库约 2 MB，编译产物通常几百 KB 到几 MB。负责 3D 渲染、模型加载（OBJ/glTF）、相机、输入与窗口管理。通过命令行 `g++/clang++` 链接静态库与系统库（`opengl32`、`gdi32`、`winmm`）即可。

画面定位为低模清爽风格化（简洁材质、雾效裁剪、可选简单阴影），不追求 F1 25 级 PBR 画面——那是高模 + 损伤形变 + 回放系统的量级，与 10 MB 预算冲突。尾翼翻转、翼片脱落/碎片等玩法视觉用模型分件 + 变换/换模实现。

### 4.2 qu3e：轻量刚体碰撞

qu3e 是紧凑 3D 物理引擎，除 C++ 标准库外无外部依赖，可 CMake 构建静态库。能力边界明确：刚体 + 盒子碰撞（OBB）+ 离散检测 + 光线投射，**没有原生轮胎/悬挂模型**。因此 qu3e 只负责刚体碰撞，车辆手感由自写动力学施加力/扭矩实现。

部件级碰撞通过在底盘复合刚体上挂附加碰撞盒（前翼、尾翼、侧箱、底板）实现；碰撞接触点坐标映射到最近部件做损伤判定。细长翼片碰撞体加厚并配合子步频率防穿模；若掠射穿模不可接受，二期评估替换为 Jolt Physics（MIT、CCD、复合凸包、自带轮式约束），静态体积增量需重新核算进 10 MB 预算。

### 4.3 ENet：主机权威网络

ENet 是轻量、基于 UDP 的可靠网络库，可 CMake 构建静态库，Windows 下链接 `winmm`、`ws2_32`。支持多通道：不可靠高频位置广播 + 可靠事件通知。社区 `raylib-extras/networking_example` 提供 8 人客户端/服务器参考框架。

### 4.4 udp-discovery-cpp：局域网自动发现

零依赖 C++ 库，CMake 构建静态库。主机以可被发现模式周期性 UDP 广播用户数据（房间码 + ENet 端口），客户端监听并列出局域网内可见主机；客户端用房间码过滤后连接对应 ENet 端口。房间码不承载安全功能，仅做逻辑匹配。

### 4.5 车辆动力学：自写 4 轮射线悬挂 + 组合滑移 Simcade 模型

qu3e 不含轮胎/悬挂，车辆手感全部由自写动力学实现，模型深度按 RR3 / Monoposto 一档拟真定标：

- **4 轮射线悬挂**：每轮向下射线求悬挂压缩 → 弹簧阻尼力求轮胎垂向载荷 → 施加到底盘刚体；四轮独立建模，支持单轮压白线/路肩/出界的抓地差异，悬挂行程直接驱动视觉轮子。
- **组合滑移轮胎**：滑移矢量（摩擦椭圆）+ 载荷敏感 Pacejka，纵向/侧向力求解见 6.3。
- **磨损/温度**：每轮独立累积滑移耗散功，峰值附着下降、曲线变钝；温度作二级修正。
- **动力总成**：引擎扭矩曲线、齿比、换挡（含动力中断）、引擎制动、差速锁止系数。
- **空气动力学状态机**：基础下压力/阻力 map + DRS + 2026 X/Z-mode 活动翼 + Override/ERS 能量管理。
- **损伤→气动映射**：部件健康度调制前后轴/总成 C_L、C_D 乘子。
- **辅助层**：ABS/TC/ESC/转向平滑/反打，叠在上述模型之上，可分级关闭。

## 6. 玩法与物理方案

### 6.1 车辆状态与输入

车辆维护位置、朝向、纵向/横向速度、横摆角速度、四轮载荷/滑移/磨损/温度、部件健康度、ERS 电量（SoC）、DRS/翼档状态、圈数、圈速、辅助状态。输入：W/↑ 油门，S/↓ 刹车/倒车，A/D 或 ←/→ 转向，Space 手刹，R DRS，E 活动翼档位/Override，C 相机，Esc 暂停。

### 6.2 碰撞与动力学分工

- **qu3e 负责**：底盘复合刚体（含前翼/尾翼/侧箱/底板碰撞盒）与静态赛道边界盒子、地面及其他车辆的碰撞检测与分辨率；防止穿墙、穿地、碰撞反弹。接触点坐标输出给损伤系统做部件映射。
- **自写动力学负责**：4 轮射线悬挂求解、每轮轮胎力（组合滑移、载荷敏感、磨损/温度）、载荷转移、下压力/阻力（受 DRS/活动翼/损伤调制）、动力总成与引擎制动、ABS/TC/ESC/转向平滑/反打辅助。
- **视觉悬挂**：轮子位置直接取自悬挂行程输出，随加速度与路面起伏真实起伏。

### 6.3 轮胎与悬挂细节

组合滑移：令纵向滑移率 κ 与侧偏角 α 合成为滑移矢量

\[
\sigma = \sqrt{\kappa^2 + \tan^2\alpha}, \quad
F_x = \frac{\kappa}{\sigma} F(\sigma), \quad
F_y = \frac{\tan\alpha}{\sigma} F(\sigma)
\]

\[
F(\sigma) = D \cdot \sin\left(C \cdot \arctan\left[B\sigma - E(B\sigma - \arctan(B\sigma))\right]\right)
\]

载荷敏感（μ 随载荷下降）：

\[
D(F_z) = D_0 \left(\frac{F_z}{F_{z0}}\right)^{n}, \quad 0.85 \le n \le 0.95
\]

每轮垂向载荷 = 静态分配 + 纵向/侧向载荷转移 + 悬挂弹簧阻尼力；下压力按前后轴比例（约 45:55）随速度平方分配到四轮。磨损按滑移耗散功率累积：

\[
W \mathrel{+}= \left(|F_x \kappa| + |F_y \tan\alpha|\right) \Delta t, \quad
m(W) = \max(1 - c_w W,\ m_{\min})
\]

抓地乘子 m(W) 同时压低峰值并使曲线变钝；温度作二级修正（冷胎/过热抓地衰减）。物理固定子步 240 Hz 起步，抖动时提高到 500 Hz（300 km/h 时单步位移约 35 cm / 17 cm，细长翼片依赖加厚碰撞体防穿模）。

### 6.4 动力总成、气动、能量与损伤

- **基础气动**：\( F_{down} = \frac{1}{2}\rho C_L A v^2 \)、\( F_{drag} = \frac{1}{2}\rho C_D A v^2 \)，前后轴分配；前/后/总成系数独立，受部件健康度乘子调制。
- **动力总成**：扭矩曲线 × 齿比 × 主减速 → 后轮驱动力；换挡含动力中断；松油门施加引擎制动；差速锁止系数影响弯中牵引。辅助层：ABS 按纵向滑移率降低制动力，TC 按后轮动力滑移削减引擎输出，ESC 按车身滑移角与横摆偏差对单前轮差动制动，转向平滑限制前轮角速率，反打辅助在侧滑时叠加修正角。默认开启、可分级关闭。
- **DRS（经典规则）**：激活区内开启，\( C_D \downarrow \)、后翼 \( C_L \downarrow \)（平衡前移→转向不足倾向），关闭后恢复。
- **2026 活动翼（X/Z-mode）**：X-mode 低阻（直线）、Z-mode 高下压力（弯道），前后翼档位切换 + 过渡曲线 + 尾翼翻转动画；可选手动前翼配平。
- **Override 超车模式**：跟车距离/时间触发超部署，受 ERS 电量（SoC）限制，含回收；与 DRS 按规则开关互斥（G-12）。
- **损伤映射**：接触点 → 最近部件（前翼 L/R、尾翼、侧箱、底板），部件健康度 0–1 → 对应 \( C_L/C_D \) 乘子 + 质量/阻力微调；掉前翼 → 转向不足，掉尾翼 → 高速不稳；视觉换模/碎片脱落。

参数调校方向：后轴 D 略高、轻微转向不足基调、下压力前后约 45:55、ABS/TC 阈值 0.15–0.25、ESC 阈值 8°–12°。

### 6.5 赛道与 AI

赛道由中心线 + 宽度生成路面与静态边界盒子；圈速按起终点线穿越判定。DRS 激活区、损伤接触点映射所需的空间查询共用赛道数据。AI 使用前视点转向 + 速度 PID，共用同一套车辆物理与辅助层（含磨损、DRS/Override 使用策略）；难度调最大速度、转向响应、刹车距离。

## 7. 联机方案

### 7.1 拓扑

**主机 = 服务器 + 玩家**。主机运行 ENet host 监听，同时作为玩家；其他客户端连接主机。主机权威裁决车辆物理与碰撞。

### 7.2 ENet 通道划分

- **通道 0（不可靠）**：高频位置/旋转/速度状态广播；客户端→主机发送输入状态；主机→客户端广播权威车辆状态。丢失不重传，下一帧覆盖。
- **通道 1（可靠）**：玩家加入/离开、比赛开始/结束、圈速完成、碰撞/损伤事件、DRS/翼档状态变更、ERS 关键状态、聊天/快捷消息等低频事件。

### 7.3 同步与插值

客户端收到远端车辆状态后不直接赋值，维护 100–150 ms 位置缓冲区，渲染时在最近两个快照间线性插值，保证视觉平滑。磨损/损伤位/SoC 等慢变状态随快照携带或经通道 1 增量同步，每车每秒数百字节量级。内网不实现复杂延迟补偿与反作弊；但网络抖动仍需插值处理。

### 7.4 自动发现与房间码流程

1. 主机点击“创建房间”，生成 4 位房间码，启动 ENet 监听与 UDP 广播；广播包含房间码 + ENet 端口。
2. 客户端打开游戏，发现层监听广播，自动列出局域网内可见主机。
3. 客户端输入房间码，过滤出匹配主机，点击加入，连接其 ENet 端口。
4. 主机接受连接并同步当前比赛状态；新玩家加入后进入赛道。

发现层使用统一应用 ID，客户端只处理同应用 ID 的广播；防火墙需允许 UDP 广播与 ENet 端口。

## 8. 渲染、资源与性能

Raylib 加载低多边形 OBJ/glTF 车辆与赛道；车辆模型按部件分件（前翼/尾翼/侧箱/底板/轮子），支持损伤换模、碎片脱落与尾翼翻转动画。纹理小尺寸压缩；音频 OGG。资源预算：车辆 2–3 个 × <500 KB，赛道 3–5 条 × <1 MB，纹理总量 <3 MB，音频 <2 MB，EXE + 库 + 资源 ≤10 MB。关闭或降低阴影，使用雾效裁剪，控制 draw call 与三角形数。目标 1080p 60 FPS（瓶颈在渲染不在物理：8 车 × 240 Hz 轮胎力求解为微秒级）。

## 9. UI、存档与分发

UI 用 Raylib 绘制或轻量立即模式 UI：主菜单、创建/加入房间、发现列表、房间码输入、HUD（含轮胎磨损/温度、ERS SoC、DRS/翼档、部件损伤提示）、暂停、结算。配置与设置写入 EXE 同级 `config.ini`（音量、画质、相机、辅助分级、玩家名），重启保留。分发为单个 EXE + 可选 `config.ini`，U 盘拷贝到 E/F 盘双击运行。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 车辆手感调参周期长（组合滑移/磨损/损伤叠加） | 先固定辅助全开保证可玩，再逐项调 Pacejka/载荷敏感/下压力；磨损与损伤各留独立乘子层，用参数表迭代；单人测试台固定圈数对比 |
| qu3e 离散检测导致翼片掠射穿模 | 翼片碰撞体加厚 + 240/500 Hz 子步；对关键接触做扫掠补丁；仍不可接受时二期换 Jolt（CCD） |
| 接触点→部件映射误判 | 最近部件 + 距离阈值 + 二次校验（法向/部位包围盒）；边界情况取保守部件 |
| qu3e 只有盒子碰撞，边界可能卡顿 | 赛道边界用规则盒子拼接；对推回与碰撞加阻尼；必要时边界改用中心线约束辅助 |
| 客户端插值窗口不当导致抖动 | 100–150 ms 缓冲区；广播频率与插值窗口联调；丢包时外推短时间 |
| 防火墙阻止 UDP 广播/ENet | README 说明允许；提供手动 IP 直连作为后备 |
| 自动发现受多网卡/虚拟网卡干扰 | 绑定指定网卡或提供选择；房间码过滤减少误连 |
| EXE 体积超预算 | 静态链接裁剪；低模资源；纹理压缩；音频 OGG；Jolt 替换需重算体积 |

## 12. 验收标准

- 单个 EXE 双击可运行，零运行时依赖，体积 ≤ 10 MB。
- 4–8 人局域网同场竞速，主机权威，远端车辆插值平滑。
- 主机创建房间后，客户端自动发现并可用房间码过滤加入，无需手动输入 IP。
- 端到端延迟理想 <10 ms、可接受 <30 ms；1080p ≥60 FPS。
- 3–5 条赛道、2–3 辆车、圈数/圈速/排名完整。
- 轮胎磨损随滑移累积，长距离圈速衰减可感知，换新胎恢复。
- DRS 在指定区激活，尾速/阻力变化正确；出区恢复。
- 活动翼两档切换有尾翼翻转视觉与明显下压力/阻力差异；Override 受电量限制、跟车触发。
- 碰撞损伤按部件生效：掉前翼明显转向不足、掉尾翼高速不稳，气动变化可通过圈速感知。
- 键盘默认辅助下可稳定驾驶；辅助分级关闭后物理更 raw。
- 配置写入 EXE 同级文件，重启保留。
- 无公网依赖。
