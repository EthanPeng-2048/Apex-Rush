状态：**S1 已实施（2026-11-23，三后端 drive-test 0 failures + bench 无退化）；S2–S6 待实现**。行为以代码与本文档为准。

## 0. 目标与动机

现状两个痛点：

1. **引擎声音难听、引擎本身不真实**。当前 `Engine` 组件是"扭矩曲线查表 + rpm 由车速锁止"（simcade）：没有曲轴动力学、没有逐缸燃烧、没有进排气声学，rpm 不会因节气门突变而有动态惯性，也没有真实转速波动。
2. **想接入开源的 Engine Simulator 原理**（[ange-yaghi/engine-sim](https://github.com/ange-yaghi/engine-sim)，MIT）——它从"每缸燃烧→缸压→曲轴扭矩→转速"的物理因果链直接模拟，**声音又是同一套缸压/进排气压力波动合成的**，音调、负载、节气门天然联动。但它是 Windows-only 的 demo（构建在 Delta 引擎上、依赖 SDL/Boost），**不能拿来当依赖**，**只抄原理、不搬代码**，把它移植进我们组件化的 `Engine`。

同时定下**架构方向**（用户裁定）：

- **疯狂拆分，但以"任务池 + 子引擎"的方式，而不是"每部件一个专用线程"**。
- 线程池数量 = 系统硬件线程数（`std::thread::hardware_concurrency()`）；所有子引擎都是**提交到池上的调度任务**，复用线程，不自开专用线程。
- **所有部件（引擎/车体/悬架/AI/空力/音频/网络）统一成同一种"子引擎"抽象**，各自**持自己的时钟频率**，互不同频（多速率协同仿真）。
- 跨子引擎只交换低带宽耦合量，用**无锁队列 + 事件总线 + 快照/插值**。
- **引擎自产音频**：引擎任务算好 PCM 提交到队列，音频线程只播。
- **物理并行是远期必然**：靠"岛/空间分区"结构并行求解器，而非并发调用 `IPhysicsWorld`。
- 目标硬件不锁死：4c/8t 要能跑，16c/32t 也要能利用（任务池按硬件线程伸缩）。

## 1. 总架构

```
             ┌────────────── 任务池（唯一；std::thread::hardware_concurrency()）──────────────┐
             │   所有子引擎 = 池上的调度任务；按各自 period 提交；复用线程，不单开专用线程        │
             └───┬────────┬─────────┬──────────┬─────────┬──────────┬─────────────────────────┘
   (1kHz)   引擎 │ (240Hz) │ (60Hz)  │ (48kHz)  │ (30Hz)  │  物理核   │  任意子引擎
             │       车体/悬架 │  AI     │  音频播放  │  网络    │  (串行 Step)
   ┌─────────▼──┐  ┌─────▼────┐  │         │          │          │
   │ 曲轴动力学  │  │ 车体物理  │  │ 每个子引擎：{state, rate, step(), in-ports, out-ports}
   │ 简化燃烧    │  │ 读引擎快照│  │ 跨引擎：无锁队列 + EventBus；快照+插值跨频
   │ 产扭矩快照  │  │ + 插值    │  │
   │ 产音频→队列 │  └──────────┘  │
   └────────────┘                │
                                 │
        EventBus / CollisionBus / InputBus（纯事件、无回调，已存在）
```

**铁律**：子引擎之间**不共享可变状态**；只通过"快照/消息"交换。共享读只读配置。

## 2. 子引擎契约（统一抽象）

每个部件是一个 `SubEngine`，满足统一接口（对齐我们已拆的组件化：Params + State + Step）：

```cpp
struct SubEngine {
    struct Port {             // 出/入耦合量（跨频只交换低带宽值）
        // e.g. engine→vehicle: torque[N]; vehicle→engine: crankSpeed[rpm], loadTorque[Nm]
    };
    struct Params { /* 本子引擎可调参（改车） */ };
    struct State  { /* 本子引擎运行时状态，只在本任务内写 */ };

    float rate;               // 本子引擎的时钟频率（可任意不同频）
    void  Step(const InputPorts&, OutputPorts&);   // 由调度器按 period 调用
    // in/out 经无锁队列/快照交换；Step 内不得锁、不得跨引擎写
};
```

**对称性**：引擎拆了，其余部件也拆（同一机制、统一抽象），不做"某个部件单开线程"的不对称设计。

**调度**：调度器维护每个子引擎的下一次触发时刻，选最早者执行（多速率、非固定 tick 对齐）。子引擎之间无隐式顺序依赖——依赖只通过端口数据表达。

## 3. 任务池（线程模型）

- 数量 = `std::thread::hardware_concurrency()`（4c/8t → 8；16c/32t → 32）。
- 所有子引擎步进 + 物理 Step + 异步加载等，全部作为任务提交到池；**没有"线程 x 专属部件"**。
- 线程切换开销在本规模（几十个任务）可忽略；任务是大量小粒度、各自独立的，超线程/更多核纯提升吞吐。
- **确定性档**：测试/联机对拍/回放需要确定性 → 提供 `Configure(0)` 串行路径（复用现有 drive-test 的 `JobSystem::Configure(0)`），调度顺序固定、无并行，保证结果可复现。

> 吞吐 vs 延迟：更多线程提升**吞吐**（可跑更多车/更高频率），但不改善**单帧关键路径延迟**（sim→render 的临界路径仍受最低频率侧约束）。竞速手感由延迟决定，所以单帧预算（60FPS→16ms）不因线程数而放宽。

## 4. 引擎子引擎（简化设计——只保留真实感影响大且开销低）

**原则**：不搬 engine-sim 完整 10kHz 逐缸燃烧（联机 8 车不可行），只保留对"引擎真实"贡献最大的原理：

### 4.1 曲轴动力学（主力，替换查表 rpm）
```
I · dω/dt = Σ(每缸气体扭矩) + 起动机扭矩 − 负载扭矩 − 摩擦扭矩
rpm = ω 动态积分                        // 转速是力平衡结果，不是查表
```
- 引入**曲轴转动惯量 I** 到 `EngineParams`（改车可调）。
- 表现：节气门突变 → 转速动态上冲；负载拖高挡 → 转速被压；松油 → 引擎制动 + 转速回落。这是"引擎真实"的最大来源，开销低（每子步一次标量积分 + 负载读入）。

### 4.2 简化燃烧（降频、保因果）
不逐缸算完整燃烧/缸压分布，保留因果：
```
节气门 → 进气量 → 燃烧能量(∝ 能量密度·AFR·效率) → 扭矩脉冲 → 曲轴
```
- 加 **曲轴转速波动**（每缸点火给一个扭矩脉冲，而非平均扭矩）——这是"声/手感联动"与发动机节奏感的关键，也是引擎自产音频的相位来源。
- 加 **点火正时 + 断油限速（rev_limit）**、**回火/失火**的随机小扰动（燃烧效率随机性）——engine-sim 的"放炮/回火"真实感来源，成本低。

### 4.3 自产音频（生产者）
引擎子引擎**自己算 PCM**（用上面的转速/点火脉冲相位 → 谐波/脉冲合成 + 进排气滤波 + 负载调制），提交到**无锁 SPSC 队列**；音频子引擎只排空播放，不算引擎声。

### 4.4 数据驱动（深度定制/改车）
把 engine-sim 的参数语义并入 `EngineParams`：曲轴惯量、缸数、点火顺序/相位、AFR、燃烧效率、红区/断油、进排气曲线。改车/换引擎 = 改 Params。

### 4.5 明确的"不做"（避免范围蔓延）
- 不做完整声学腔（进排气管容积/卷积的精确还原）——用滤波 + 脉冲合成达到"好听"即可。
- 不做 F1-2026 混动语义（ERS/空力我们自己已有，引擎只管燃烧/曲轴/声音）。
- 不搬 engine-sim 的 Delta 引擎 / 渲染 / .mr 脚本运行时——只抄算法原理。

## 5. 多速率闭环契约（关键稳定性设计）

引擎↔车体是**闭环反馈**（引擎扭矩→车加速→车速→引擎 rpm→扭矩），且现在被允许**不同频**。契约：

- 耦合量只走**低带宽快照**：
  - 引擎→车体：`torque[Nm]`（引擎 rate，如 1kHz）
  - 车体→引擎：`crankSpeed[rpm] + loadTorque[Nm]`（车体 rate，240Hz）
- 消费方读**最新快照 + 线性插值**（复用现有三缓冲快照思路，跨频插值）。
- **稳定性**：跨速率闭环有相位延迟风险（尤其在低速率侧）。处理：插值窗对齐 + 必要时把闭环里**频率最低的一段**锁存对齐（一次性同步点），避免振荡。**这是设计契约，不是免费假设**——落地时要有闭环稳定性回归（转速不发散/不振荡的断言）。
- **不要求所有子引擎同频**：AI 60Hz、车体 240Hz、引擎 1kHz、音频 48kHz、网络 30Hz 各自为政，互不挂钩。

## 6. 物理子引擎

- **现状**：`IPhysicsWorld::Step`（qu3e）**必须串行**，且后端非线程安全。今天物理核作为串行子任务在池上跑。
- **远期**：物理并行 = **结构并行**（岛/空间分区，参考 Jolt/Bullet 多线程求解器），**不是**"每个部件并发 ApplyForce"。到那一步再改后端/自己拆岛；接口层现在留好边界（`IPhysicsWorld` 已是抽象，可换并行后端）。
- 车体/悬挂/轮胎仍走 physics 后端；它们与引擎的耦合经第 5 节契约，不并发碰 world。

---

## 7. 确定性契约

- 调度器多线程输出随线程时序变化 → **确定性档** `Configure(0)`：串行、固定调度顺序，用于 drive-test / 联机对拍 / 回放。
- 每种子引擎可**脱离调度器单测**（沿用组件化接口：给输入端口、调 Step、断言输出端口）——可测试性是最低门槛。

---

## 8. 性能预算

- 单帧（渲染 60FPS → 16ms）内，物理核（240Hz 串行 Step）+ 车体 + 引擎低带宽耦合，要在余量内。
- 引擎高频（1kHz）**不占物理线程**：它在池上用自己的周期；车体 240Hz 读它的快照插值。
- 吞吐随线程数伸缩：4c/8t 能跑、16c/32t 充分利用（任务池自适应）。
- 音频：引擎产 PCM 的带宽可控（一车 1–2 声道 × 48kHz×32bit ≈ 380KB/s），无锁队列无阻塞。

### S1 实施记录（2026-11-23）

**曲轴动力学**（`Engine::Step`，physics.cppm `EngineParams` 新增）：曲轴惯量、进气滞后、点火相位/扭矩脉冲、断油限速（滞回 12500/12150）、种子化失火（xorshift，可复现）、怠速调速器 + 200rpm 防熄火地板、摩擦（c0+c1·ω）+ 节气门泵气组成的引擎制动（替代旧 wheel-side 90Nm·0.25）。

**传动耦合（关键决策）**：刚性锁止——驱动轮从动于曲轴（`TireModel` slaved 模式，滑移率输出用命令轮速修正）；曲轴方程负载 = **实测后轮反作用（轮胎力 + 刹车扭矩）**经挡位反射。滑移经轮胎力负反馈收敛，刹车/加速/巡航瞬态自稳定（试错记录：若负载改用"空阻+前轮阻力"则刹车时前轮减速快于命令轮速、传动被拉开、后轮反推车；若惯量再反射整车质量则与 Fx 反馈双算质量、起步减半）。

**离合器**：仅在静止怠速断开（防蠕行），其余全时结合；刹车不断开（Fx 反馈已稳定）。换挡：换挡判定用**刚性匹配转速**（防自由空转棘轮升挡），挡位变化时曲轴按新速比刚性缩放（离合断开时跳过）。

**扭矩曲线**：峰值下平顶（F1 式）——起步需要 gas 超过抓地反射负载否则曲轴被压在防熄火地板。怠速下 `TorqueFactor` 钳制 ≥0.72 防负扭矩。

**AI 适配**：刚性传动使刹车效率 ~77-80%（前刹须连带减速传动惯量），AI 弯速预算 0.95→0.90（`Game.cpp` AI 速度目标）。

**验证**：drive-test 三后端 0 failures（起步/极速/换挡/高速点刹/倒车/刹车/AI 走廊全过）、threaded-smoke 0 failures、bench 16 车 qu3e 1.909s（≈基准 1.9s 无退化）。WASM 冒烟未跑（本机未配置 EMSDK）。

## 10. 验收

- **引擎真实**：转速随节气门动态、负载拖低高挡、松油引擎制动、断油/回火可见——不再是查表转速。
- **引擎声音**：随 rpm/负载联动的程序化声，由引擎自产并提交，音频线程只播。
- **多速率**：引擎/车体/AI/音频不同频运行，不强制挂钩；闭环稳定（转速不振荡断言）。
- **任务池**：线程数 = `hardware_concurrency()`，所有子引擎为池上任务、无专用线程；4c/8t 与 16c/32t 均可跑。
- **确定性**：`Configure(0)` 下 drive-test 全后端 0 failures；每种子引擎可脱离调度器单测。
- **组件解耦**：引擎不并发碰 `IPhysicsWorld`；物理 Step 串行，为远期结构并行留接口。
