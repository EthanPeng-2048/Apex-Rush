## ADR-01 主机是唯一权威（主机即服务器）

**决策**：主机模拟全部车并裁决一切（圈数/排名/完赛/损伤/复位）；客户端只发送输入。

**理由**：单一权威不是"加一层"，而是**删掉一整类逻辑**——不需要协商、不需要收敛分歧、不需要每人权威的状态切换；圈数、接触、损伤只有一个来源，赛后可以逐字段对账。

**备选与否决**

| 方案 | 否决原因 |
|---|---|
| 每人权威自己那台车（P2P） | 每台机要模拟全部车 + 维护 N 套重同步；且"谁先过线/谁把谁推歪"没有裁决者。看起来省了服务器，实际多出一整套分歧处理 |
| 专用服务器进程 | G-01 规定主机即服务器；headless 只留作测试工具 |

**代价**：主机 CPU 承担 8 车 240 Hz（`--bench 100` 已证明余量）；主机退赛即散场。

## ADR-02 客户端只预测自己的车（回滚重放）

**决策**：客户端 240 Hz 本地推进**且仅推进自己的车**，输入立即生效；收到快照后按 `appliedInputSeq` 回滚到权威状态、重放未确认输入。

**理由**：把"网络往返 + 快照节流"整段从响应通路里摘掉，联机手感 ≈ 同帧率单机（验收 A5：差 ≤2 ms）。这是 CS2 一类竞技游戏的同一套做法。

**备选与否决**

| 方案 | 否决原因 |
|---|---|
| 不预测，本地车也由快照驱动 | 输入要绕一圈网络才见效，赛车是连续闭环操作，不可接受 |
| 预测但不回滚，只把位姿吸附到权威 | 物理状态停在旧输入上继续算，高速下发飘 + 持续抖动 |
| 远端车也本地模拟（输入复制） | 需要全车输入分发 + 共享时间线 + 分歧收敛，属过度设计；收益只是"别人的车早几十毫秒"，而玩家本来就依据自己屏幕上的画面操作 |

**代价**：客户端多跑 1 台车的物理（μs 级）；需要 M0 的状态存取。

## ADR-03 别人的车：快照插值 + 只挡不推的碰撞代理

**决策**：远端车不做本地物理。① 位姿按快照环形插值（缓冲 33–150 ms 自适应，LAN 默认 ~40 ms）；② 每台远端车在本地世界里挂一个 `mass = 0` 的碰撞体，每 tick 用插值位姿 `SetTransform` 推过去。

**理由**：插值是竞技游戏里"别人的位置"的标准取舍——玩家的操作依据是自己屏幕上看到的，而不是主机真值。碰撞代理只解决"会被穿过去"这个最刺眼的缺陷，成本约 20 行，且**不引入第二个作者**：远端车的位姿从头到尾只有主机一个来源，所以不存在"本地算完又要覆盖"的回弹问题。

**备选与否决**

| 方案 | 否决原因 |
|---|---|
| 远端车无碰撞体（可穿过） | 视觉与手感都错，贴身缠斗完全失真 |
| 远端车作为动态体本地模拟 | 需要别人的输入 + 共享时间线 + 冲击同步，等于把 v3 那套补丁全请回来 |
| 远端车运动学体可被推动 | 一旦本地能推它，就要在权威状态到达时"拉回"，即回弹 |

**代价**：远端车在本地不可推动（我撞它只我被弹），这与主机裁决一致；插值带来的 25–50 ms 视觉延迟是 N-05 的要求。

## ADR-04 子模块新增 `Vehicle` 状态存取（M0）

**决策**：向 `rush-engine` 加 `VehicleSnapshotState` + `Vehicle::SaveState()/RestoreState()`，纯增量。

**理由**：回滚重放必须能把车恢复到"可继续推进"的状态；现有 `Vehicle::Reset(pose)` 会清零胎耗/温度/ERS/损伤（`physics.cppm:1185`、`vehicle_impl.cpp:861-883`），用它回滚等于每次校正都把轮胎磨平。

**约束**：不改 `Reset` 语义与任何现有调用路径；`--drive-test` 三后端 0 failures、`--bench` 分段计时不变；M0 门禁是"存档→跑 10 tick→恢复→重跑同样输入→逐位相等"。

## ADR-05 手写位打包编解码

**决策**：`src/net/protocol/` 用显式小端读写 + 定点量化，纯函数、定长报文。

**理由**：报文全定长（22 / 345 / 27 / 60 / 21 B…），手写能锁死尺寸（`static_assert`）、能写金标准字节测试、零新依赖（NF-01 ≤10 MB）。protobuf/flatbuffers 引入数百 KB 代码与变长尺寸；`#pragma pack` + memcpy 布局/端序不可控。

**代价**：字段变更必须手改编解码并升 `protoVer`——这是特性（可审计的字节）。

## ADR-06 输入语义：电平 + 3 帧冗余 + 边沿单调计数

**决策**：连续量（油门/刹车/转向）按"最新值优先"，每包带最近 3 帧；翻转量（DRS/翼档/Override）用 u8 单调计数，接收端按有符号差分只应用一次；两端共用同一 `InputSmoother`（1–2 tick 线性）。

**理由**：连续量丢一帧无害；翻转量在冗余重发下必须恰好生效一次。输入不带时间戳——主机在下一个 tick 应用，不需要时钟同步。

**备选与否决**：lockstep（一个客户端卡顿全场冻结）；输入带 tick 戳 + 主机侧插值队列（需要时钟同步，收益为零）。

## ADR-07 发现层自写 Winsock 广播

**决策**：主机 1 Hz 广播 `ANNOUNCE`（70 B），客户端监听 + 主动 `QUERY`（主机单播回应）；不引入 udp-discovery-cpp。

**理由**：功能只要一个 70 B 定长报文；新依赖与体积/许可成本不划算（NF-01）。`QUERY` 单播兜底是广播被防火墙/多网卡挡住时唯一的自救路径。

**可替换**：`IRoomDiscovery` 后面还有 `StaticDiscovery`（测试/同机双开）与 `NullDiscovery`（WASM）。

## ADR-08 规则与结算只由主机裁决

**决策**：客户端不调用 `UpdateRace`；圈数/排名/完赛/损伤全部来自快照与事件。客户端本地不估算成绩。

**理由**：两套实现的边界条件（复位传送、擦边过线、掉帧）不可能一致，屏幕上会先给错数字再改。丢包风险由可靠有序事件通道 + 主机状态机"迁移瞬间产生一次"解决。

---

## ADR-09 范围裁定（不作为，是决定）

不做：中途加入（N-06）、AI 混编（G-06）、掉线重连、手动 IP 直连、文本输入（房间码用数字滚轮）、反作弊/延迟补偿、客户端命中判定。
理由：内网自包含场景 + 用户裁定；每一项都要引入独立的状态机或额外的信任面，与"简单但强大"冲突。

| tick 软同步（±5% 变速、lead_ticks）（v3） | 只服务于"本地模拟别人的车"的共享时间线；不模拟别人就不需要 |
